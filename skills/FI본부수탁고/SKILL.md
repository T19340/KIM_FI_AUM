# FI본부수탁고 — 본부 수탁고 리포트 생성

`D:\복호화\FI운용본부_수탁고양식_new.xlsb`의 수작업(CSV 붙여넣기 → 팀분류 수식 복구 →
피벗 날짜 교체 매크로 → 값붙여넣기 매크로)을 대체하는 파이썬 도구를 실행한다.
업무 규칙 상세는 도구 폴더의 `BUSINESS_LOGIC.md`, 운영 상태는 `README.md` 참고.

## 도구 위치와 기본 명령

```
폴더:   C:\Users\USER\Cowork\2026-07-23_수탁고-자동화
생성:   python make_report.py              (rawdata 최신 처리일 기준)
        python make_report.py --date YYYY-MM-DD
BOS갱신: python update_bos.py <BOS3218_YYYYMMDD.xlsx 경로>
검증:   python verify.py                   (엑셀 원본 재현 회귀검증, PASS 633 기준)
산출:   K:\부서 공유\FI운용본부\본부 수탁고 현황\FI운용본부수탁고_YYYYMMDD.xlsx
        (template\FI운용본부수탁고_양식.xlsx 을 채운 사본. --out 으로 변경 가능,
         K: 미연결이면 로컬 output\ 으로 물러남)
원천:   K:\부서 공유\FI운용1부\10. 개인별폴더\김현수\rawdata\MOS2101_YYYYMMDD.csv
```

산출 폴더가 곧 부서 정본 위치이고 `수탁고_메일발송.py` 도 그 폴더에서 첨부 파일을
찾는다. 같은 이름의 파일이 이미 있으면 덮어쓰기 전에 경고 줄로 기존 수정일을 알리므로,
손으로 만든 파일을 지우는 상황이 아닌지 확인하고 넘어간다.

## 진행 원칙

1. **시작하면 먼저 상태를 한 줄로 보고한다**: 데이터 최신 처리일, 이번에 새로 반영될
   CSV 일자, BOS3218·수익자 매핑 최종 갱신일, 다이어트 보류 상태.
2. rawdata에 더 최신의 `BOS3218_*.xlsx`가 있으면 `update_bos.py`를 먼저 실행한다.
   자가검증·변경 diff 가드가 내장되어 있으며, "부재 구역 0행" 또는 "최종모펀드 변경
   50건 초과"로 중단되면 원인을 파악하기 전에 강행하지 않는다.
3. `make_report.py` 실행 후 **경고 출력을 그대로 사용자에게 전달한다** — 특히
   수익자 매핑 없는 신규 사모펀드, 양식 명단에 없는 수익자, 부서별 표 구조 변경.
4. 완료하면 산출 xlsx를 사용자에게 보내고, 주요 증감(본부 계·팀별)을 요약한다.

## 날짜 규칙 (부서별 표의 열)

구분 / 2년전 연말 / 1년전 연말 / 직전 분기말 / 직전 월말 / 현재 순.
분기말·월말은 "당일이 그 말일이면 이전 말일"로 물러난다 — 7월이면 분기말=월말=6/30이라
QTD=MTD가 되는 것이 정상. `pick_dates()`가 자동 처리하므로 손댈 필요 없다.

## 수익자 매핑 갱신 (사용자가 알려줄 때)

- `data\수익자.csv`에 행 추가: 열1=펀드코드(5자리), 수익자1~3.
- **클래스(종) 단위로 매핑한다** — 클래스 합=모(운용펀드) 원본액이므로 모는 비워둔다.
- 배분이 비대칭이면 `수익자N수탁고` 열에 가중치(예: 300/1)를 적는다. 없으면 균등.
- 새 수익자 기관은 **양식 파일**(template\FI운용본부수탁고_양식.xlsx)의 수익자 표
  B/F/J열에도 행을 추가해야 리포트에 표시된다 (명단의 기준은 양식 파일).
- **테두리 규칙**: 굵은 테두리는 표 바깥 경계 표시 — 각 표의 '가장 아래 행'
  아래에만 둔다. 표 끝에 행을 추가하면 ①새 마지막 행에 기존 마지막 행 서식을
  복사하고 ②기존 마지막 행의 아래 테두리를 내부 행 서식으로 되돌린다
  (내부 행 서식 복사가 간단: 예 `F82:I82` 서식 → `F83:I83` PasteSpecial).
- 명칭 주의: '한투밸류자산운용'으로 통일, '건강보험'(공단 아님),
  'NH은행(퇴직)'류는 일반 은행과 별도 수익자.
- **뉴에이스 시리즈(모 + 1종·2종)는 1종·2종에만 붙이고 모는 비운다.** 6·7·8호가
  모두 같은 형태다 — 6호 08L51 건강보험 / 08L52 한투밸류자산운용, 7호 08M61 건강보험 /
  08M62 한투밸류자산운용, 8호 08N57 건강보험 / 08N58 한국투자저축은행. 종류형 모
  (운용펀드) 행도 수익자 배분 모집단에 들어가므로 모와 클래스를 함께 매핑하면
  이중계상된다. 새 호수가 생기면 1종·2종 수익자를 사용자에게 확인한다(추측 금지).

## 엑셀 원본 대비 의도된 차이 (정정 사항)

숫자를 원본 엑셀과 대조할 때 이 4건만 다르면 정상:
① 본부계 ETF NAV — 원본 G49 수식 오류 정정. ② 수익자 표 — 원본 SUMIF 범위(P150)
버그 정정. ③ 수익자 배분 — 균등 1/n 대신 가중 배분. ④ 수익자3 몫 포함(원본은 누락).

## 문제가 생기면

- 검증이 필요하면 `verify.py` (참조 테이블은 워크북 시점 스냅샷 `data\*_asof_20260715.csv`로
  고정되어 있어 운영 갱신과 무관하게 PASS 633이 나와야 정상).
- 상하위 표에 "전액 감소"가 여럿 보이면 BOS 갱신 사고(마커 소실)부터 의심 —
  `update_bos.py`는 반드시 openpyxl 경로로 읽는다(pd.read_excel 금지).
- **양식·산출물 xlsx에 openpyxl로 저장 금지** (읽기는 무방) — 데이터 막대의 x14 확장
  (0축·음수 붉은 역방향)이 벗겨진다. 값 기입·행 추가 등 모든 쓰기는 Excel COM으로.
  산출물에서 막대가 사라졌다면 openpyxl 저장이 끼어든 것.
- COM에 날짜를 쓸 때 datetime 객체를 넘기면 로컬→UTC 보정으로 9시간 밀린다 —
  엑셀 일련번호 정수로 쓴다 (`make_report._xlserial` 참고).

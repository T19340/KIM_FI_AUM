# KIM_FI_AUM — FI운용본부 수탁고 계산·리포트 도구

`D:\복호화\FI운용본부_수탁고양식_new.xlsb` 로 하던 수탁고 집계(CSV 붙여넣기 → 팀분류
수식 복구 → 피벗 날짜 교체 매크로 → 값붙여넣기 매크로)를 파이썬으로 대체한다.
엑셀 원본과 전수 대조해 **PASS 633 / FAIL 0** 을 확인한 구현이다.

- 임의 기준일의 수탁고를 콘솔에서 조회: `aum.py`

- 업무 규칙의 근거와 원본 워크북 버그: [`BUSINESS_LOGIC.md`](BUSINESS_LOGIC.md)

## 1. 새 컴퓨터에서 설치

```bash
git clone https://github.com/T19340/KIM_FI_AUM.git
cd KIM_FI_AUM
pip install -r requirements.txt
```

비공개 저장소이므로 최초 1회 GitHub 인증이 필요하다. 가장 간단한 방법:

```bash
gh auth login          # GitHub CLI. 브라우저로 T19340 계정 로그인
```

`gh` 가 없으면 clone 할 때 사용자명과 **Personal Access Token**(비밀번호가 아니라
github.com → Settings → Developer settings → Tokens, `repo` 권한)을 입력하면 된다.
한 번 인증하면 이후에는 `git pull` 만으로 최신 코드를 받는다.

```bash
git pull        # 이후 업데이트는 이 한 줄
```

## 2. 사용법

### 2-1. 수탁고 조회 — `aum.py`

```bash
python aum.py                                   # 가장 최근 처리일 기준
python aum.py --date 2025-12-31                 # 기준일 지정
python aum.py --date 2025-12-31 --name ESG      # 펀드명에 'ESG' 포함분 별도 집계
python aum.py --date 2025-12-31 --name ESG --list   # 해당 펀드 전건 나열
python aum.py --dates                           # 사용 가능한 처리일 목록
python aum.py --no-csv                          # K: 드라이브를 보지 않고 히스토리만
```

출력 예 (2025-12-31, 억원):

```
펀드일임구분         펀드       일임      MMF      ETF         계
FI운용1부    23879.2  11433.4  59993.9  18688.4  113994.9
FI운용2부    91245.2  71236.8        -   1260.4  163742.4
해외FI운용부   22458.9   2036.8   3867.3  43840.6   72203.5
본부 계     137583.3  84707.0  63861.2  63789.4  349940.9

본부 계 349,940.9 억원 (34.99 조원), 344건
```

`--name` 을 주면 팀별·유형별 내역과 함께, **이중계상 방지로 제외된 모펀드 행**을
참고로 같이 보여준다(클래스 합과 모펀드 금액이 맞는지 눈으로 확인하는 용도).

지정한 날짜가 처리일에 없으면 그 이전의 가장 가까운 처리일로 물러나며, 그 사실을
`!` 로 시작하는 줄로 알린다.

### 2-2. 월말기준수탁고 리포트 — `make_report.py`

```bash
python make_report.py                     # rawdata 최신 처리일 기준
python make_report.py --date 2026-07-14   # 기준일 지정
python make_report.py --csv-dir "D:\some\rawdata"   # rawdata 경로 변경
```

`template/FI운용본부수탁고_양식.xlsx` 사본에 값을 채워
`output/FI운용본부수탁고_YYYYMMDD.xlsx` 를 만든다. 실행 중 나오는 **경고 줄은 그냥
넘기지 말 것** — 수익자 매핑이 없는 신규 사모펀드, 모펀드에 붙은 매핑(클래스와
겹치면 이중계상), 양식 명단에 없는 수익자, 부서별 표 행 구성 변경을 알려준다.

리포트 두 열(2025YE·현재)마다 **대조 한 줄**이 따라 나온다.

```
  대조 [현재] 수익자 배분 206,655.7억 / 사모 계상 206,655.7억 → 일치
```

수익자 배분 합과 부서별 표의 사모 계상 총액이 같으면 미매핑도 이중계상도 없다는
뜻이다. 차이가 나면 위의 경고 줄이 그 원인을 짚어 준다.

기준일 5종(2024YE·2025YE·직전분기말·직전월말·최신)은 자동 판정한다. 분기말·월말은
"당일이 그 말일이면 이전 말일"로 물러나므로, 7월 기준일에서 분기말=월말=6/30이 되어
QTD와 MTD가 같아지는 것은 정상이다.

### 2-3. BOS3218(모자펀드 관계) 갱신 — `update_bos.py`

```bash
python update_bos.py "K:\...\rawdata\BOS3218_20260721.xlsx"
python update_bos.py --selftest       # 파생 규칙 자가검증만
```

자가검증과 이전본 대비 diff 가드가 들어 있다. **"부재 구역 0행"** 또는
**"최종모펀드 변경 50건 초과"** 로 중단되면 원인을 파악하기 전에 강행하지 말 것 —
과거에 이 가드가 없어 모펀드 부재 마커가 소실되면서 단독 종류형 펀드들이 피벗에서
통째로 사라진 사고가 있었다. 이전본은 `data/bos3218_prev.csv` 로 백업된다.

### 2-4. 수익자 매핑 갱신 — `data/수익자.csv`

신규 사모·일임 펀드가 설정되면 행을 추가한다. 열1=펀드코드(5자리), 수익자1~3.

- 매핑은 **클래스(종) 단위**로. 클래스 합 = 모(운용펀드) 원본액이므로 모는 비워둔다.
- 배분이 비대칭이면 `수익자N수탁고` 열에 가중치를 적는다(예: 삼성카드 300 / 저축은행 1).
  비우면 균등 배분.
- 새 수익자 기관이면 **양식 파일**(`template/FI운용본부수탁고_양식.xlsx`)의 수익자 표
  B/F/J열에도 행을 추가해야 리포트에 표시된다. 명단의 기준은 양식 파일이다.
- 양식에 행을 추가할 때 굵은 테두리는 표의 가장 아래 행 아래에만 둔다. 끝에 행을
  추가하면 새 마지막 행에 서식을 복사한 뒤, 기존 마지막 행의 아래 테두리를 내부 행
  서식으로 되돌린다.
- 명칭은 '한투밸류자산운용'으로 통일, '건강보험'(공단 아님), 'NH은행(퇴직)'류는 일반
  은행과 별도 수익자로 취급한다.

## 3. 수탁고 정의 (모든 명령 공통)

| 항목 | 규칙 |
|---|---|
| 금액 | `기획실수탁고분류` = ETF는 순자산(후), 그 외는 **원본액**, 억원 단위 |
| 대상 | 운용부서 ∈ {FI운용본부, 공동} |
| 이중계상 방지 | 모자구분 ∈ {일반펀드, 자펀드} · 종류형구분 ∈ {일반펀드, 판매펀드} |
| 제외 | 제외조건 = "" (가상펀드 3JM54 제외) |
| 본부 계 | 팀분류 ∈ {FI운용1부, FI운용2부, 해외FI운용부} 합 |
| 기준 축 | **처리일** (영업일이 아니라 CSV 파일명의 날짜) |

펀드/일임/MMF/ETF 구분(`펀드일임구분`)은 위에서부터 먼저 걸리는 것으로 확정한다 —
ETF → MMF → (투자신탁 & 공모·사모)면 펀드 → 투자일임이면 일임. 리포트의 달성률에서는
일임·MMF의 YTD가 '펀드' 목표에 합산된다.

파생열 15종과 피벗 9개의 정의는 [`BUSINESS_LOGIC.md`](BUSINESS_LOGIC.md) 참고.

## 5. 주의할 점

- **양식·산출물 xlsx에 openpyxl로 저장하지 말 것** (읽기는 무방). 데이터 막대의 x14
  확장(0축·음수 붉은 역방향 막대)이 통째로 벗겨진다. 모든 쓰기는 Excel COM으로 한다.
- **COM에 날짜를 넘길 때는 엑셀 일련번호 정수로.** datetime 객체를 넘기면 로컬→UTC
  보정이 끼어들어 9시간 밀린다 (`make_report._xlserial`).
- **BOS3218 xlsx는 openpyxl로 직접 읽는다.** `pd.read_excel` 은 '모펀드 부재 시작'
  마커인 빈 문자열을 NaN으로 바꿔 구역 전체가 앞 블록을 상속하게 만든다.
- **엑셀 원본과의 의도된 차이 4건** — 숫자를 원본 워크북과 대조할 때 이것만 다르면
  정상이다. ① 본부계 ETF NAV(원본 G49 수식 오류 정정) ② 수익자 표(원본 SUMIF 범위
  P150 버그 정정) ③ 수익자 배분(균등 1/n 대신 가중) ④ 수익자3 몫 포함(원본은 누락).
- **`MOS2101_YYYYMMDD_추가.csv` 는 자동 반영되지 않는다.** `build_dataset()` 이
  `MOS2101_<8자리>.csv` 만 읽기 때문이다. 실제로 2025-12-31에 이런 파일이 있었고
  그 안의 1행(5JM20 한화변액연금Ⅱ, 1,294.1억)이 빠지면 본부 계가 349,940.9 →
  348,646.8억으로 달라진다. 해당 일자는 워크북 히스토리에 포함돼 있어 지금은 영향이
  없지만, 앞으로 `_추가` 파일이 붙는 일자가 생기면 그 행은 누락된다.
- 리포트 양식의 열 머리글은 2024YE/2025YE로 고정돼 있다. 2025년 이전 기준일로
  리포트를 만들면 연도 라벨이 실제와 어긋나므로 양식을 손봐야 한다.
- 히스토리의 2025-12-30 이전 행은 파생열이 **당시 기준 저장값 그대로 동결**돼 있다
  (팀분류 기준 변경 이력 보존). 2026-01-02 이후 행은 현행 수식과 완전히 일치함을
  12,500행에서 확인했다.
